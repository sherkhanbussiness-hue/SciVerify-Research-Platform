Build a polished, production-quality web application called **SciVerify — Scientific Code-Execution Reliability Harness**.

I am building SciVerify as an AI-for-Science research project. The purpose of the platform is to evaluate whether AI agents can solve scientific problems by generating executable Python code, successfully executing that code, producing scientifically valid results, and doing so reproducibly.

This is NOT a generic AI chatbot.

The application should look and feel like a serious **AI research/evaluation platform**, similar in quality and visual sophistication to modern products such as Linear, Vercel, OpenAI research tooling, Anthropic Console, Weights & Biases, and modern observability platforms.

I have attached a visual reference image named:

Use this image as the primary visual inspiration for the interface, layout, typography, spacing, dashboard structure, cards, charts, navigation and overall aesthetic.

Do NOT simply copy the image.
Use it as a design reference and create a coherent, responsive implementation.

==================================================
CORE PRODUCT
============

SciVerify evaluates AI-generated scientific code.

The basic workflow is:

User selects a scientific task
↓
AI agent receives task
↓
Agent generates Python code
↓
Code is executed in a controlled environment
↓
Execution success/failure is recorded
↓
Generated output is compared with reference answer
↓
Scientific correctness is evaluated
↓
Metrics are calculated
↓
Results are stored
↓
User can inspect code, logs, outputs and visualizations

The central question is:

**"Can an AI agent produce scientific code that actually works and produces a correct, reproducible result?"**

==================================================
CRITICAL SAFETY / EXECUTION REQUIREMENT
=======================================

Never execute arbitrary AI-generated Python code directly on the main application server without isolation.

The eventual execution system must be designed around a sandbox/containerized execution environment with:

* resource limits
* timeout
* restricted filesystem
* restricted network access
* controlled dependencies
* process isolation

For the initial Replit prototype, use simulated/mock execution results instead of executing arbitrary generated code.

Clearly separate:

Demo execution

from

Production sandbox execution.
